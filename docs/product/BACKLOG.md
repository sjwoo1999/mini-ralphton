# BACKLOG

## 5.1 도출 규칙
도출 규칙은 사람 확정 PRD에서 미충족 G#를 찾는 것으로 시작한다.
현재 가장 큰 미충족 목표는 G5 의사결정 지원이다.
그 다음 G5를 인용하는 F# 중 미구현 또는 부분구현 항목을 찾는다.
시드로 골든 스케치를 만들 수 있는 항목을 먼저 고른다.
기존 S1~S9와 제목이나 로직이 중복되면 다음 후보로 넘긴다.

## 5.2 후보 요약
| spec | 인용 | 제목 | 골든 스케치 |
|---|---|---|---|
| spec-8 | F8 ← G5 | 점수 분해 표시 | score 입력요소를 카드 노드로 분리하고 총점과 합성 일치 |
| spec-9 | F2/F3/F4 ← G2/G3 | 입력 배선 | DOM 이벤트 후 리스트 id 집합이 코어 함수 결과와 일치 |

## 5.3 spec-8 점수 분해 표시
목표는 G5 의사결정 지원이다.
현재 점수 배지는 총점만 보여준다.
사용자는 총점의 이유를 알 수 없으므로 콘센트, 와이파이, 24시간, 좌석 판단을 카드 안에 분리한다.
골든 측정방법은 seed의 한 카페를 입력으로 점수 구성요소 배열을 만들고, 구성요소 합이 `score(cafe)`와 같은지 비교하는 것이다.
S4 점수 함수와 중복되지 않게 UI 노드 존재를 검증 대상으로 둔다.

## 5.4 spec-9 입력 배선
목표는 G2 조건 필터링과 G3 탐색성이다.
현재 필터, 검색, 정렬 코어 함수는 존재하지만 단일 페이지 입력과 완전히 연결되지 않았다.
콘센트 select, 검색 input, 정렬 버튼 이벤트를 결과 배열 compose로 연결한다.
골든 측정방법은 `outlets === many`, 이름 부분검색, 점수순 정렬의 코어 결과를 seed에서 재도출하고 DOM id 집합과 비교하는 것이다.
이 spec은 S2, S5, S4를 다시 구현하지 않고 UI 이벤트와 렌더 갱신만 다룬다.

## 5.5 spec-10 활성 필터 요약
목표는 G5 의사결정 지원이다.
필터가 적용되었을 때 사용자는 목록이 왜 줄었는지 알아야 한다.
헤더에 적용 조건과 결과 수를 노출한다.
골든 측정방법은 필터 상태 객체를 입력으로 요약 문자열을 만들고, 동일 상태에서 렌더된 헤더 텍스트를 비교하는 것이다.
이 spec은 필터 결과를 계산하지 않고 설명 텍스트만 책임진다.

## 5.6 spec-11 심야 카공 모드
목표는 B 포지셔닝 보조 전략이다.
심야 사용자는 24시간 운영, 대형 좌석, 많은 콘센트를 동시에 원한다.
프리셋은 `open24h ∩ seats >= 50 ∩ outlets === many` 조건으로 정의한다.
골든 측정방법은 보호 시드에서 조건식을 실행해 id 집합을 도출하고 UI 프리셋 결과와 비교하는 것이다.
이 spec은 일반 필터의 조합을 단축 버튼으로 제공할 뿐 새 데이터 필드를 만들지 않는다.

## 5.7 spec-12 즐겨찾기 필터 뷰
목표는 G4 개인화다.
현재 즐겨찾기 토글과 저장은 구현되어 있지만 즐겨찾기만 보는 뷰는 없다.
사용자는 저장한 카페만 다시 확인할 수 있어야 한다.
골든 측정방법은 jsdom에서 여러 id를 토글한 뒤 즐겨찾기 필터를 적용하고 렌더 id 집합이 localStorage id 집합과 같은지 비교하는 것이다.
이 spec은 S8 저장 로직을 다시 만들지 않고 목록 필터 뷰만 다룬다.

## 5.8 중복 방지
spec-8은 S4를 반복하지 않고 점수 설명 UI를 검증한다.
spec-9는 S2, S3, S5, S7의 코어 함수를 반복하지 않고 입력 이벤트 연결을 검증한다.
spec-10은 필터 로직이 아니라 사용자가 보는 요약을 검증한다.
spec-11은 기존 필터의 합성 프리셋이며 새 필드를 만들지 않는다.
spec-12는 S8 저장 로직이 아니라 저장된 집합을 보는 화면을 검증한다.
