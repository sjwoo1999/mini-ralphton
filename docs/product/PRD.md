# PRD

## 1.1 문제 정의
카공족은 지금 갈 만한 카페를 고를 때 일반 지도 서비스 안에서 너무 많은 판단을 직접 한다.
네이버지도와 카카오맵은 위치와 리뷰를 잘 보여주지만, 콘센트 유무, 와이파이, 24시간 영업, 좌석 규모를 공부 관점에서 한 번에 비교하지 못한다.
사용자는 리뷰를 열고, 사진을 훑고, 영업시간을 다시 확인하고, 결국 감으로 고른다.
카공지도는 이 탐색 비용을 줄이기 위해 카페를 공부적합 기준으로 정렬한다.
핵심 문제는 정보가 아예 없는 것이 아니라, 공부 결정에 필요한 정보가 순위로 변환되지 않는 것이다.
그래서 앱의 첫 화면은 지도가 아니라 비교 가능한 리스트가 된다.

## 1.2 타깃 사용자
1차 사용자는 노트북 작업이 필요한 대학생, 프리랜서, 취업 준비생이다.
이들은 장시간 머무르기 때문에 콘센트와 좌석 규모를 강하게 본다.
와이파이와 심야 운영도 단순 편의가 아니라 작업 지속성의 조건이다.
2차 사용자는 카페 투어를 하면서도 작업 가능성을 버리지 않는 카공족이다.
이들은 분위기와 접근성도 보지만, 최소한 공부 가능한 상태인지 빠르게 확인하고 싶어 한다.
따라서 카공지도는 감성 탐색 앱이 아니라 공부 장소 의사결정 도구로 정의한다.

## 1.3 가치 가설
G1 비교 가능성 측정: 모든 카페가 `score()` 결과로 같은 척도에서 정렬되고, 동점일 때도 결정적으로 순서가 정해진다.
G2 조건 필터링 측정: 콘센트, 와이파이, 24시간, 좌석규모 조건이 각각 독립 또는 복합으로 적용되어 시드 기준 부분집합을 반환한다.
G3 탐색성 측정: 이름 부분검색과 거리순 정렬이 사용자의 목적지 도달 시간을 줄이는 방향으로 작동한다.
G4 개인화 측정: 즐겨찾기는 localStorage를 단일 진실원으로 삼아 재방문 시 같은 목록을 복원한다.
G5 의사결정 지원 측정: 사용자가 왜 특정 카페가 상위인지 점수 구성요소와 활성 필터 요약으로 설명받는다.
이 앱이 존재할 단 하나의 이유는 공부적합 지표를 통해 카페를 비교하고 순위로 보여주는 것이다.
일반 지도는 위치를 보여주고, 카공지도는 순위를 보여준다.
공부적합 점수는 콘센트, 와이파이, 24시간, 좌석 조건을 사용자가 해석하기 쉬운 파생 지표로 바꾼다.
G5는 현재 미충족 가치 축이며 다음 출하 1순위로 둔다.

## 1.4 목표
### G1 비교 가능성
모든 카페는 공부적합 점수를 가진다.
점수는 같은 입력에서 항상 같은 정수를 반환해야 한다.
동점일 때 정렬이 흔들리면 리스트 신뢰가 깨지므로 보조 정렬 기준을 둔다.
측정은 score 함수와 정렬 테스트의 종료코드로 한다.

### G2 조건 필터링
사용자는 콘센트, 와이파이, 24시간, 좌석규모 조건을 직접 걸 수 있어야 한다.
각 조건은 독립으로도, 조합으로도 적용 가능해야 한다.
조건 결과는 시드 기준으로 재현 가능해야 한다.
측정은 필터 함수가 반환한 id 집합을 보호 시드에서 재도출한 기대집합과 대조한다.

### G3 탐색성
사용자는 이름 일부를 검색해 후보를 줄일 수 있어야 한다.
사용자는 기준점에서 가까운 순서로 후보를 볼 수 있어야 한다.
거리 계산은 좌표 기반 순수함수로 유지해 캐시와 UI 상태에 의존하지 않는다.
측정은 이름 검색 테스트와 haversine 거리 정렬 테스트로 한다.

### G4 개인화
사용자는 마음에 드는 카페를 즐겨찾기로 저장할 수 있어야 한다.
저장값은 페이지 재렌더나 함수 재호출 뒤에도 유지되어야 한다.
localStorage가 단일 진실원이므로 인메모리 캐시로 인한 desync를 만들지 않는다.
측정은 토글, 재토글, 깨진 저장값 폴백, 렌더 버튼 상태를 jsdom에서 검증한다.

### G5 의사결정 지원
사용자는 목록 1위가 왜 1위인지 납득할 수 있어야 한다.
점수 총합만 보여주면 블랙박스가 되므로 콘센트, 와이파이, 24시간, 좌석 판단을 분해해 보여준다.
활성 필터 요약은 현재 목록이 어떤 조건으로 좁혀졌는지 알려준다.
측정은 카드 안 점수 분해 노드와 헤더 요약 노드의 jsdom 존재 검증으로 한다.
G5는 다음 출하 1순위이며 spec-8, spec-10으로 분리한다.

## 1.5 비범위
지도 렌더링은 현재 범위가 아니다.
Leaflet 같은 지도 라이브러리는 jsdom 기본 검증으로 신뢰하기 어렵기 때문에 v0.x에서 제외한다.
실시간 혼잡도, 크롤링, 외부 API 연동도 하지 않는다.
로그인과 서버 계정은 만들지 않는다.
즐겨찾기는 localStorage로 충분하며 서버 동기화는 지금의 문제를 해결하는 데 필요하지 않다.
리뷰, 평점, 사진 업로드도 현재 제품의 핵심 차별점이 아니다.
가격, 소음도, 운영시간 상세, 행정동은 확장 후보로만 둔다.

## 1.6 킬 기준
K1: 사용자 검증에서 공부적합 점수가 실제 선호와 어긋나는 사례가 연속 측정되면 점수 모델을 폐기하거나 가중치를 재정의한다.
K1의 발동 임계는 동일 사용자가 아닌 서로 다른 사용자 세션에서 점수 상위 후보를 반복적으로 배제하는 신호가 확인되는 경우다.
이때 단순 불만 한 건으로 접지 않고, 점수 구성요소 중 어떤 항목이 원인인지 로그와 인터뷰를 분리한다.
K2: 사용자가 필터와 정렬을 쓰는 것보다 일반 지도 검색이 더 빠르다고 반복 측정되면 제품을 접는다.
K2의 발동 임계는 핵심 과업이 일반 지도 대비 시간 또는 클릭 수에서 이득을 보이지 않는 경우다.
K2가 발동하면 기능을 더 붙이지 않고 카공지도 v0.x 포지션이 무의미하다고 판단한다.

## 1.7 악마의 절
의심 A: 카페 정보 앱은 이미 많아서 차별점이 약하다.
답 A: 경쟁 서비스가 주지 않는 것은 정보가 아니라 공부 관점의 순위다.
카공지도는 콘센트, 와이파이, 24시간, 좌석을 공부적합 점수로 변환한다.
파생지표 자체가 제품 정체성이므로 점수 투명성은 방어 가능한 해자다.
G5를 강화하면 사용자는 점수를 믿거나 반박할 근거를 얻는다.

의심 B: 범위가 넓으면 일반 지도와 같은 싸움을 하게 된다.
답 B: 그래서 전국 카페 탐색이 아니라 심야 카공 같은 좁은 순간으로도 포지셔닝할 수 있다.
open24h, 좌석규모, 콘센트는 새벽 작업자에게 직접적인 조건이다.
시드는 이 조합을 실측할 수 있으므로 데모에서 즉시 보여줄 수 있다.
이 방향은 A를 버리는 것이 아니라 순위 지표를 더 선명한 사용 순간에 적용하는 보조 전략이다.

의심 C: A와 B 모두 반응이 없으면 계속 만들 이유가 없다.
답 C: 그 경우 K2에 따라 종료한다.
카공지도는 기능 수를 늘리는 앱이 아니라 의사결정 비용을 줄이는 앱이다.
그 비용이 줄지 않으면 제품 가설은 실패한 것이다.
